## a. 项目说明

### 功能介绍

「面镜」是一款 **AI 表达力练习小程序**：用户在小程序里选一道题（或上传自己的简历/论文由 AI 生成针对性的题），对着手机说 3 分钟，60 秒内拿到：

- 五维能力雷达图（内容 / 结构 / 表达 / 节奏 / 专业度）
- 逐句批注（哪些句子有问题、怎么改）
- 优点 + 可执行改进建议 + 200 字示范回答
- 客观表达数据（语速 / 填充词密度 / 口头禅 / 长停顿 / 时长分配）
- 可分享的成绩海报

此外提供一条**深度面试链路**：上传简历 → AI 结构化解析（可逐项核对修正）→ 岗位能力分析
→ 生成 15~20 道与简历强关联的面试题 → 逐题作答（可展开追问与参考答案要点、记录用时）
→ **六维岗位能力雷达 + 优势/短板分别说明 + 四类可执行优化建议**（知识补强 / 简历优化 /
表达改进 / 练习方向）。

2026-10-27 新增**题库抽题（批量模式）**：自选学科科目（覆盖哲学、经济学、法学、教育学、
文学、历史学、理学、工学、农学、医学、军事学、管理学、艺术学十三个学科门类的 1302 道内置题，
每科 ≥100 题）→ 按科目配比随机抽 10~15 题一次性展示 → 依次作答后统一交卷 → AI 统一评分，
输出**按科目维度的掌握度图谱（雷达）+ 逐题点评 + 针对性学习建议**；LLM 不可用时确定性
规则降级，评分功能始终可用。

### 目标用户

- 大三/大四学生：秋招模拟面试
- 研究生：开题/中期/毕业答辩预演
- 本科生：课堂展示、竞赛路演

### 使用场景

覆盖 **课堂展示 → 课程答辩 → 求职面试** 的连续链路，把"表达力"这一校园高频但长期缺少工具的软技能，做成可量化、可追踪、可分享的练习产品。

### 核心流程

**链路一 · 单题表达练习**

选场景 → 抽题（或上传材料生成题）→ 限时录音 → 转写（可修正）→ AI 评估 → 雷达图 + 逐句批注 → 分享海报 → 复盘

**链路二 · 深度面试（简历驱动）**

上传简历 → 结构化解析（教育/实习/项目/获奖/技能，用户可确认或修正）→ 填写目标岗位
→ 岗位核心能力与考察维度分析 → 生成 15~20 道强关联面试题 → 逐题作答（追问 / 要点提示 / 用时记录）
→ 六维能力雷达 + 优势短板 + 四类优化建议

> 演示录屏片段见提交材料（`演示视频/`）。

### 内容安全与合规（UGC 检测策略说明）

本项目有 3 处用户产生内容（UGC）会进入云端链路，均已接入微信官方 `security.msgSecCheck`
（`version: 2`、`scene: 2` 评论场景、content 截断至 2500 字）：

| UGC 入口 | 云函数 | 检测位置 | 处理 |
|---|---|---|---|
| 人工修正后的转写文本 | `updateTranscript` | 写入 `practices` 记录前 | 违规必拒；降级留痕 `seccheck` / `seccheckReason` |
| 录音转写结果 | `asr` | 落库前 | 同上 |
| 上传的简历/论文材料 | `genQuestions` | 进入 LLM 链路前 | 违规必拒；降级痕迹记入云端日志 |

**检测策略（两条，互斥且都要）**：

1. **违规内容一律拒绝** —— `suggest === "risky"` 时返回业务错误 `{ error }`，
   不进入后续链路、不落库。**降级逻辑不会放过违规内容**（回归测试对此有专门断言，
   删除该守卫即测试变红）。
2. **检测服务不可用时降级放行 + 留痕** —— 平台侧接口故障（`61010` 用户访问记录超时、
   `45009` 超每日配额、`44991` 超每分钟限制、`-604101` openapi 权限缓存未生效、
   `-1` 系统繁忙、`-501001` 云端系统错误）时，若一律拒绝会导致
   「录音 → 转写 → 评估 → 报告」整条主链路不可用。因此此类故障**降级放行**，
   并写入可审计字段：`seccheck = "unavailable"`、`seccheckReason = "code=… 原始原因"`，
   可事后复核。降级原因同时打印到云函数日志（`[sec-check] msgSecCheck 失败 code=… reason=…`）。

> ⚠️ **如实披露**：本项目在内容安全检测接口不可用时采取的是「降级放行 + 留痕可审计」，
> 而非绝对 fail-close。违规内容在任何情况下都会被拒绝，但平台检测不可用的窗口期内，
> 存在未过检内容被放行的可能（该窗口内所有放行记录均可通过 `seccheckReason` 追溯）。
> 代码位置：`cloudfunctions/{updateTranscript,asr,genQuestions}/sec-check.js`
> （云函数不能跨目录 require，三处为同源副本，测试断言三者一致）。

## c. 创新点说明（六维度）

1. **AI 应用创新**：把"表达力评估"从主观感受变成 **LLM 语义评估 + 规则化表达分析** 的双引擎量化，真融合而非聊天框。
2. **场景创新**：覆盖课堂展示 → 答辩 → 面试的连续场景，深耕校园垂直人群。
3. **产品创新**：★核心差异化 = **自定义出题**——上传简历/论文摘要，AI 像评委一样针对材料生成追问（"模型精度提升 12%"→ 追问基线/消融/测试集口径），把"通用陪练"变成"针对我的陪练"。
   ★2026-10-26 进一步升级为**简历驱动的深度面试链路**：简历结构化解析（教育/实习/项目/获奖/技能，用户可核对修正）→ 岗位能力标准 → **15~20 道与简历强关联**的面试题（每题强制携带简历锚点 `evidence`，杜绝通用题）→ 逐题作答（追问 / 要点提示 / 用时记录）→ **六维岗位能力雷达 + 优势短板分述 + 四类优化建议**。跨页进度落云端，中途退出可续答；**LLM 未配置时全链路降级仍可跑通**（规则解析 + 模板出题 + 确定性总结）。
4. **技术创新**：**规则化表达分析**——语速、填充词、口头禅、长停顿、时长分配全部确定性计算（零成本、更精确），与 LLM 文字点评互补。
5. **商业模式创新**：C 端会员次数 + B 端院校就业中心采购（见落地规划）。
6. **用户体验创新**：转写可人工修正（ASR 误差兜底）、报告 60 秒内生成、订阅消息通知、成绩海报社交裂变。

## d. 技术实现

### 核心架构

```
小程序（原生 + TS）
  ├─ 页面：index(选场景) / question(出题) / record(录音) / result(报告) / history(历史)
  │        + resume(简历解析·岗位) / deep(逐题作答) / deep-report(六维总结)
  ├─ 组件：radar-chart(原生Canvas雷达) / sentence-note(逐句批注) / share-poster(海报)
  └─ utils：api / expression(规则化表达) / recorder / interview(深度面试共享类型)
        │ wx.cloud.callFunction
        ▼
云函数（Node.js，18 个）
  login / submitPractice / asr / analyze / finalize / genQuestions / getPractice
  / getQuestions / getHistory / updateTranscript
  + parseResume / analyzeJob / genDeepQuestions / deepSession / deepAnalyze（深度面试）
  + quizDraw / quizScore（刷题抽题与判分）
  + getWxacode（分享海报小程序码，FR-11）
        │
        ├─ 腾讯云 ASR（录音文件识别）
        ├─ LLM（DeepSeek/Qwen/GLM，OpenAI 兼容）
        └─ 云数据库 collections: practices / quota / rate_limits / questions / interviews
```

### 关键难点与解决方案

| 难点 | 解决方案 |
|---|---|
| 云函数 20 秒超时 | 拆分短函数串联（submitPractice → asr → analyze → finalize），客户端 3s 轮询状态 |
| LLM 评分不稳定 | 温度 0.2 + JSON Schema + 提供"重新评估"入口 + 报告缓存 |
| LLM 延迟 | 全异步化，前端"AI 正在生成报告，约 40 秒"进度提示 |
| 语音识别方言/噪音 | 提供转写人工修正入口（同时是体验加分项） |
| 表达维度难以量化 | 规则化计算（语速/填充词/停顿），不交给模型 |
| 评分证据可信 | LLM 必须引用原话作为证据（`quote` 原文照抄） |

### 深度面试链路的技术设计

> 本节展开说明「简历驱动深度面试」的三项关键设计：**状态管理**、**题目数据结构**、**异常处理**。

#### ① 整体流程的状态管理

**两层状态分离**：

**A. 页面级状态机**（管 UI 渲染与防重入）

| 页面 | 状态流转 | 关键 flag |
|---|---|---|
| `resume` | `upload → uploading → parsing → review → job → generating → ready` | `uploading` / `parsing` / `analyzingJob` / `generating` |
| `deep` | `loading → ready → answering → scoring → (next \| completing → done)` | `loading` / `submitting` / `completing` |
| `deep-report` | `loading → (ready \| failed)` | `loading` / `analyzing` |

**B. 跨页状态落云端 `interviews` 集合**（不依赖页面栈）

```
{ _id, openid, status, resume, job, competency,
  questions[15-20], answers[], currentIndex, report, createdAt, updatedAt }
status: draft → questions_ready → in_progress → analyzing → done
```

- 每题作答**立即**写回云端；
- 页面每次 `onShow` 都 `deepSession/get` 拉取 → **中途退出 / 页面被系统杀掉都能续答**；
- `currentIndex` 由服务端维护为「第一个未答题的序号」，前端不自行推算。

**C. 为什么逐题评分在答题时同步做**

若把 15~20 题的评分攒到最后一次性做，单次云函数调用要串行 15~20 次 LLM 调用，
必然撞上云函数 20 秒超时。改为「每提交一题做一次单题评分」（每次仅 1 次 LLM 调用）后：
- 单次调用只做一件事 → 天然规避超时；
- 用户每提交一题立刻看到得分与要点反馈 → 交互体验优于「答完全部才出结果」；
- 最终总结只需 1 次 LLM 调用。

**D. 铁律落实**（详见 README《状态锁铁律》）

按钮**永不使用 `disabled` 属性**做防重入（`scripts/static_check.js` 自动检查 11 个页面）；
防重入统一走 `utils/nav-guard.ts` 的**时间戳锁**（3s 自动过期）+ `onShow` 兜底复位；
业务前置条件走 JS 拦截 + 可操作提示，与防重入**严格分离**。

#### ② 题目生成的数据结构设计

```ts
// miniprogram/utils/interview.ts —— 前后端共用同一份口径常量
export const MIN_QUESTIONS = 15;
export const MAX_QUESTIONS = 20;

export interface InterviewQuestion {
  id: string;             // "q1".."q20"，服务端重排保证连续
  question: string;       // 题干
  type: "project" | "technical" | "business" | "scenario" | "behavior";
  difficulty: "简单" | "中等" | "困难";
  competency: "technicalDepth" | "projectAuthenticity" | "businessInsight"
            | "problemSolving" | "jobFit" | "communication";   // 6 维考察点
  evidence: string;       // ★简历锚点：指向简历中真实出现的项目/公司/数字
  followups: string[];    // 追问（≤3）
  keyPoints: string[];    // 参考答案要点（≤5，同时是评分依据）
  estimatedSec: number;
}
```

**出题四级补齐链**（`genDeepQuestions`）——保证用户永远拿到 ≥15 道题：

```
LLM 出题（要求 18 道，每题必带 evidence）
  → 归一化（字段补默认 + type/difficulty/competency 白名单过滤）
  → 去重（题干归一化取前 60 字符建 set）
模板题（按简历项目/经历/获奖/技能生成）→ 补到 15
岗位通用题（18 道兜底）→ 极端情况补到 15
  → 截断到 20，重排 id
```

**硬约束**：
- `evidence` 必须指向简历真实内容 → 杜绝「介绍一下你自己」这类通用题；
- 单题评分的 `missed` 必须是该题 `keyPoints` 的子集（服务端过滤）→ 防止 LLM 自造扣分项；
- 返回 `coverage.byType / byCompetency / byDifficulty` 覆盖度统计，供前端展示题库分布。

#### ③ 异常情况的处理方式

**上传 / 解析失败**（`parseResume`）

| 异常 | 处理 | 用户看到 |
|---|---|---|
| 格式不支持（白名单外） | 服务端白名单 `/\.(txt\|md\|docx\|pdf)$/i` 拦截 | 「仅支持 .txt / .md / .docx / .pdf 格式的简历」 |
| 扫描件 / 图片版 PDF | 服务端 `pdf-parse` 提取文字 < 30 字时明确报错 | 「PDF 可能是扫描件或图片版…请改用 docx / txt 格式重新上传」 |
| 越权下载他人简历 | `fileID` 含 `/{openid}/` 归属校验 | 「无权访问该简历文件」 |
| 文件损坏 / docx 结构异常 | 区分「换文件」与「改格式」 | 「简历解析失败：文件无法读取…」 |
| 内容为空 / 不足 20 字 | 长度闸门 | 「简历内容为空 / 过短」 |
| 违规内容 | `msgSecCheck` 拦截（违规必拒） | 「简历内容包含违规信息」 |
| 命中 prompt 注入 | **不采信 LLM**，降级规则解析 | 「检测到可疑指令，请仔细核对」 |
| **LLM 未配 Key / 调用失败** | **降级规则解析**，仍返回结构化草稿 | 弹窗「AI 解析暂不可用，已按关键词规则识别…请逐项核对」 |

> ★最重要的是最后一条：**LLM 不可用时功能不中断** —— 用户拿到规则识别的结构化草稿
> + 明确告警，而不是一个报错页。

**题目数量不足**（三级防线）

1. **服务端**：四级补齐链保证 ≥15；极端不足时返回 `countWarning` 如实告知；
2. **前端拦截**：`< 15` 时**不静默放行** —— 弹 modal「题目数量不足（实际 N/15）…请回到上一步补充细节后重新生成」，
   且**不写入云端会话**、**不进入 ready 步骤**；
3. **进入答题前二次校验**：`onStartInterview` 再查 `[15,20]` 区间，越界则拦截并提示重新生成。

**答题中途异常**

| 异常 | 处理 |
|---|---|
| 单题评分 LLM 失败 | 中性分 3 分 + 「评分暂不可用，已记录你的回答」，**不丢答案** |
| 回答命中注入 | 中性分 3 分 + 标记待人工关注，**不采信 LLM 输出** |
| 页面中途退出 | 答案已逐题写回云端 → 重进自动续答到 `currentIndex` |
| 正在输入时 `onShow` 触发 | `hasDraft` 判定保留本地草稿，**不被云端空答案覆盖** |
| 提交失败 | `submitting` 归位 + 错误可见 |
| 越权访问他人面试记录 | `doc.openid !== OPENID` → 「无权访问该面试记录」 |
| **数据库集合 `interviews` 不存在**（`-502005`） | 识别错误码并翻译成可操作文案：「请先在云开发控制台创建该集合（权限选「仅创建者可读写」）」，**不再吞成「请重试」** |

> ⚠️ 集合是**手动创建**的（不在云函数部署脚本覆盖范围内），是本链路部署时最容易漏的一步。
> 因此「集合不存在」与「文档不存在」必须分开处理：前者给建集合指引，后者才提示重新开始。
> 回归测试 A9 双向断言这两条路径互不误伤。

**验证情况**：`tests/deep_flow.test.js` 17 场景 / 132 断言全过，
含 4 项**反向验证**（人为破坏实现 → 对应断言必须变红）：
破坏反馈保留 → 1 项红；破坏草稿保护 → 1 项红；破坏模板补齐 → 4 项红；破坏越权校验 → 2 项红。

### 关键代码片段

```ts
语速(字/分钟)  = 字数 / 有效时长 * 60        // 180-240 正常
填充词密度(%)  = count(填充词) / 总字数 * 100
                  // 口径：填充词表在 FR-08 七词基础上扩展"然后呢""这个"，共九词，验收按代码口径
口头禅         = 2-gram 高频 Top3
长停顿次数     = 相邻句时间戳间隔 > 2s 的次数
时长分配       = 开场/主体/结尾 占比，主体 <60% 判结构失衡
```
